## S1 视觉编码器与 token（8 问）

### Q1 ★★★ ViT 是怎么工作的？一张图变成多少 token 怎么算？

**A**：把图像切成固定大小的 patch（如 16×16），每个 patch 展平后线性投影成一个 token，加上位置编码，送入标准 Transformer 编码器。token 数 = (H/p) × (W/p)。

现场可背的例子：
- 224×224、patch 16 → 14×14 = **196 个 token**
- 384×704（车载常见分辨率）、patch 16 → 24×44 = **1056 个 token**
- 384×384、patch 14 → 27×27 = **729 个 token**

**追问**：为什么 patch 越小越好但也越贵？→ token 数平方增长，attention 是 O(N²)，显存和算力都吃紧；SAM/LLaVA-1.6 用更小 patch 换细节，代价是 token 爆炸，所以要配 token 压缩。

### Q2 ★★ CLS token 是干什么的？必须有吗？

**A**：ViT 沿用 BERT 的做法，在序列最前面加一个可学习的 `[CLS]` token，靠 self-attention 汇聚全局信息，做分类时只取它的输出。**不是必须的**：ViT 论文里也试过对 patch token 做全局平均池化（GAP），效果接近；现代多模态模型大多**不用 CLS**，直接把所有 patch token 交给 LLM（因为下游要的是每个位置的细粒度特征，不是单一向量）。

### Q3 ★★ ViT 和 CNN 的本质区别？为什么大模型都用 ViT？

**A**：CNN 有强归纳偏置（局部性、平移等变、权重共享），小数据下更强；ViT 只有全局注意力、没有这些先验，**必须有大数据或强增广/蒸馏才能超过 CNN**，但一旦数据够，它的表达能力和"和 LLM 同构"的优势就出来了。

用 ViT 的真实原因：① 结构同构，方便和多模态 LLM 拼装；② 全局感受野，适合需要长程关系的任务；③ scaling 行为好（参数/数据同比例涨，loss 平滑下降）。

**追问**：Swin 怎么补回局部性？→ 窗口内注意力 + 窗口移位（shifted window）做跨窗交互 + 分层下采样，复杂度从 O(N²) 降到 O(N)。

### Q4 ★★ 多模态里位置编码有哪些选择？RoPE 为什么能外推？

**A**：四类——正弦绝对编码、可学习绝对编码、**RoPE（旋转位置编码）**、ALiBi（按距离线性衰减 bias）。

RoPE 的做法：把 q/k 的相邻两维看成一个二维向量，按位置 m 旋转 m·θ 角度，于是内积只依赖相对位置差 (m-n)。**能外推是因为它编码的是相对距离，不是绝对下标**；但直接外推会随距离增大而失真，所以要配位置内插（PI）、NTK-aware 缩放、YaRN 这些方法扩上下文。

**追问**：图像 token 用 2D RoPE 怎么搞？→ 行列各一套频率（Qwen2-VL 就是 M-RoPE：时间/高/宽三套）。

### Q5 ★★ 高分辨率图像怎么处理？（这是多模态工程的核心问题之一）

**A**：四条主流路线：
1. **固定放大**（LLaVA-1.5 用 336×336 或 448×448）——简单但细节丢失、宽高比失真。
2. **切块 + 缩略图**（LLaVA-1.6/InternVL 的 dynamic tiling）：把大图切成若干 336 块，每块独立编码，再加一张全局缩略图。token 数变成块数×(块 token)+缩略图 token。
3. **原生动态分辨率**（NaViT、Qwen-VL 的 M-RoPE）：直接按原分辨率切 patch，不缩放。
4. **像素重排/pixel shuffle**（InternVL）：把相邻 2×2 个 patch 在通道维拼起来，token 数直接降 4 倍，用空间换通道。

**追问**：token 变多有什么代价？→ ① LLM 的 prefill 变慢、KV cache 变大；② 图文 token 比例失衡，注意力被图像挤占。

### Q6 ★★★ 视觉 token 太多怎么压缩？

**A**：五类手段，按"是否可学习"排：
1. **池化/重采样**（平均池化、Perceiver Resampler 用固定数量 query 做 cross-attention）——**Q-Former/Perceiver 就是这一类，把可变长 patch 压成固定 32/64 个 token**。
2. **token merge**（相邻相似 token 合并，如 Token Merging、LLaVA-PruMerge）。
3. **空间重排**（pixel shuffle，2×2 拼通道，token ÷4）。
4. **重要性剪枝**（按注意力分数保留 top-k token）。
5. **只取关键帧/区域**（视频/大图场景）。

**你的接口话术**："我在 BEV 里做的就是同类问题——7 个视角的 patch token 经深度分布加权投影到 65,536 个 BEV query 上，本质是几何约束下的 token 重组；换成 VLM 就是把 query 数量压到 LLM 预算内。"（**这句是本文档最有价值的一句话，务必背下来**）

### Q7 ★ ViT 的预训练方式有哪些？

**A**：① 监督分类（ImageNet）；② **对比学习**（CLIP 图文对比、DINO 自蒸馏无标签）；③ **掩码重建**（MAE，遮 75% patch 重建像素，训练效率高）；④ 生成式（BEiT 预测离散 visual token）。多模态场景主流是 CLIP/SigLIP 这类图文对比预训练，因为它天然对齐了文本空间。

### Q8 ★★ 一张 4K 图（3840×2160）patch 14 直接切，token 多少？为什么不能这么干？

**A**：274×154 ≈ **42,196 个 token**。对比：LLaMA-2 的上下文是 4096。所以不可能直接喂——必须缩放、切块、压缩三选一（见 Q5/Q6）。这也是"端侧多模态"最现实的约束：**分辨率是 token 的来源，token 是算力和显存的货币**。

## S2 图文对齐与经典模型（12 问）

### Q9 ★★★ CLIP 是怎么训练的？损失函数是什么？

**A**：双塔（图像塔 ViT/ResNet + 文本塔 Transformer），各自编码后投影到同一维度并 L2 归一化，得到 B×B 的相似度矩阵。**对角是正样本对，其他 2(B-1) 个都是负样本（in-batch negatives）**，损失是对称的 InfoNCE：

```text
L = 1/2 · [ CE(图像→文本) + CE(文本→图像) ]
```

即图像侧做一次 softmax 分类（正确文本是 label），文本侧再做一次。温度 τ 是可学习标量（CLIP 里初始化为 0.07 的倒数形式，即 logit_scale=1/τ）。

**追问**：为什么必须有 in-batch negatives？→ 没有负样本，模型会把所有图文映射到同一点（坍缩）。负样本的多样性直接决定表征质量，所以**大 batch 是 CLIP 的关键**（原始实现 batch 32768）。

### Q10 ★★ CLIP 怎么零样本分类？

**A**：把每个类名套进 prompt 模板（如 "a photo of a {class}"）编码成文本向量，图像向量与所有类文本向量算余弦相似度，取最大。**prompt 工程很关键**（CLIP 论文用了 80 个模板做集成），因为文本侧的训练分布是"句子"而非"单词"。

### Q11 ★★ CLIP 的局限有哪些？

**A**：① 只做**全局粗粒度**对齐，不擅长细粒度属性、计数、空间关系（"左边的红球"）；② 词序不敏感（bag-of-words 倾向，"dog bites man" 和 "man bites dog" 难分）；③ 需要海量数据、大 batch；④ 只能做判别式检索，不能生成；⑤ 对分布外/罕见概念泛化差。

**追问**：怎么补？→ 加 region-level 监督（GLIP/RegionCLIP）、加 captioning loss（BLIP）、交给能生成的多模态 LLM。

### Q12 ★★ SigLIP 和 CLIP 的区别？

**A**：把 softmax 的**多分类交叉熵换成逐对 sigmoid 二分类（pairwise sigmoid loss）**。好处：每个图文对独立判断，不再需要全 batch 归一化，**因此 batch 可以小、也能做分布式异步**，训练更省内存；效果同级甚至更好，是现在很多开源 VLM（PaliGemma、Qwen-VL 系）的视觉塔选择。

### Q13 ★ BLIP-2 的 Q-Former 是干什么的？为什么要有它？

**A**：Q-Former 是一个小 Transformer，内含**固定数量（32/64 个）可学习的 query**，通过 cross-attention 从冻结的图像编码器抽取信息，输出固定长度的视觉 token。

它解决两个问题：① **把可变长 patch token 压成固定长度**，让 LLM 的上下文可控；② **在冻结视觉塔和冻结 LLM 的前提下做桥接**，只训这一个轻量模块，成本极低。

两阶段训练：**阶段一表征学习**（ITC 图文对比 + ITM 匹配 + ITG 生成，用 query 学对齐）；**阶段二生成学习**（把 query 输出接到冻结 LLM，用语言建模损失训）。

**追问**：Q-Former 和 Perceiver Resampler 有什么区别？→ 同一类东西（固定 query + cross-attention），Flamingo 的 Perceiver 是纯重采样后用 gated cross-attention 注入，BLIP-2 的 Q-Former 还要多任务监督、对齐得更强。

### Q14 ★★★ LLaVA 为什么用两层 MLP 就够了？这和 Q-Former 的取舍是什么？

**A**：LLaVA 的消融显示：**在冻结视觉塔 + 冻结 LLM 的设定下，简单线性/MLP 投影和 Q-Former 效果接近甚至更好**，而且更简单、训练更快。原因是视觉塔已经产出了足够好的语义特征，桥接层只需要做"维度对齐 + 轻量变换"，复杂的压缩反而损失信息。

**取舍**：MLP 保信息但 token 多（贵）；Q-Former 压 token 但要多阶段训练、实现复杂。**决定因素是你的 token 预算**：预算宽松（图少、上下文长）用 MLP；预算紧（视频、端侧）用 query 压缩。

LLaVA 两阶段：① 冻结 LLM 只训 projector（用图文对做"描述生成"式对齐）；② 解冻 LLM 做指令微调（LLaVA-1.5 约 558K 预训练 + 665K 指令数据）。

### Q15 ★★ Flamingo 的结构有什么特别？

**A**：三件套——**冻结的视觉编码器**（NFNet）+ **Perceiver Resampler**（把任意数量视觉特征压成固定数量）+ **在冻结 LLM 里插入 gated cross-attention 层**（用 tanh 门控初始化 0，保证训练初期不破坏原 LLM 行为，这是很漂亮的设计）。它支持交错图文（多图 + 多轮）输入，是小样本多模态能力的代表。

### Q16 ★ 为什么大家都冻结视觉塔？

**A**：① 视觉塔参数量大（ViT-L 约 300M），冻结省显存和算力；② 预训练视觉特征已经很通用，微调反而容易过拟合到指令数据的分布；③ 冻结后视觉侧可以离线预抽特征（或者用更小的学习率）。**什么时候该解冻**：目标任务和预训练分布差很远（医学影像、红外、深度图）、或者需要极细粒度定位时，常见做法是解冻最后几层 + 小学习率。

### Q17 ★ 图文匹配里常见的三种 loss 是什么？

**A**：**ITC**（image-text contrastive，对比学习，学全局对齐）、**ITM**（image-text matching，二分类判断是否匹配，需要融合后的细粒度特征，常用 hard negative 挖掘）、**ITG**（image-grounded text generation，给定图像生成文本，用 causal mask 防止信息泄漏）。BLIP 就是三者联合，各自的 attention mask 不同——这是它设计上的巧思。

### Q18 ★ 图文对数据从哪来？质量怎么保证？

**A**：来源：网页 alt-text 抓取（量最大、噪声也最大）、人工标注（小但准）、合成（用强模型给图生成 caption）、业务数据（你自己的场景）。质量控制三板斧：① **过滤**（短文本、非自然语言、重复、比例异常图、水印图）；② **重写 caption**（用强 VLM 重新描述，把 alt-text 的噪声换成结构化描述，这就是 LLaVA-1.5 / ShareGPT4V 的做法）；③ **去重**（图像近重复是评测泄漏的最大来源）。

**你的接口**：这块你极强——数万 个场景、百万级 个关键帧的真值生产线，口径核查、版本反转 bug、双 seed 噪声地板，这些方法论完全可以直接讲成"大规模多模态数据的生产线与质量治理"。

### Q19 ★★ 如果图像和文本的 token 在序列里混排，怎么区分它们？

**A**：靠**特殊 token + 位置/模态标识**：用 `<image>`/`<|image_pad|>` 这类特殊占位 token 标出图像区间；位置编码上，文本用文本位置，视觉 token 用 2D（或 3D）位置，或者干脆共享一个序列位置（多数实现）。更细的做法是加**模态嵌入**（modality embedding）或**视觉 token 的类型标记**，让模型知道这段是"看来的"不是"读来的"。

### Q20 ★★★ 多模态里的"对齐"到底是哪几层对齐？

**A**：三层，面试时按层说很清晰：
1. **表征对齐**（representation）：图像和文本映射到同一语义空间——CLIP 干这个。
2. **粒度对齐**（granularity/region）：把文本里的"猫"对应到图像里的某个区域——Q-Former、grounding 数据、RefCOCO 监督干这个。
3. **行为对齐**（behavior）：让模型按人类偏好/指令回答——SFT + RLHF/DPO 干这个。

**你的接口**："我做的视觉-激光融合是第一层的跨模态对齐（不同传感器到统一 BEV 空间），配合几何标定做第二层的空间对齐；多模态 LLM 的第三层行为对齐是我要补的。"

## S3 多模态大模型架构与训练（12 问）

### Q21 ★★★ 一个多模态 LLM 由哪几部分组成？

**A**：三件套 + 两处细节：
1. **视觉编码器**（ViT/SigLIP）——把图变成 token；
2. **模态桥接层**（projector / Q-Former / resampler）——维度与数量对齐；
3. **语言模型**（LLM）——统一在 token 序列上做自回归。

细节：图像/文本的**特殊占位 token** 与位置编码方案；训练时的**冻结/解冻策略**。数据流是 `image → ViT → 桥接 → 与文本 token 拼接 → LLM → 文本输出`。

### Q22 ★★★ VLM 的训练分几个阶段？每阶段干什么？

**A**：三阶段，每阶段的"目的—数据—冻结策略"都不同：

| 阶段 | 目的 | 典型数据量 | 冻结策略 | 损失 |
|---|---|---|---|---|
| ① 预训练/对齐 | 让视觉特征能被 LLM 读懂 | 数十万~数百万图文对（caption 形式） | 冻结 ViT + LLM，**只训 projector** | 语言建模（生成 caption） |
| ② 指令微调 SFT | 学会按指令回答、多轮、拒答 | 数十万~百万条指令数据 | 解冻 LLM（或加 LoRA），ViT 常冻结 | 只在回答部分算 LM loss |
| ③ 偏好对齐 | 对齐人类偏好、减少幻觉 | 数万~数十万偏好对 | 全参或 LoRA | DPO / PPO / GRPO |

**关键点（加分）**：SFT 时**只对 assistant 回复算 loss，用户提问部分 mask 掉**；阶段 ① 用冻结 LLM 是为了不让随机初始化的 projector 把 LLM 带崩。

### Q23 ★★ 指令数据怎么造？

**A**：四条来源：① 人工标注（质量最高、最贵，如 LLaVA 的 GPT-4 生成 + 人工筛）；② 强模型蒸馏（GPT-4V 生成对话，注意**只用它生成文本、不用它生成图像**）；③ 现有数据集转换（VQA、检测、OCR、grounding 数据改写成对话）；④ 合成负样本/拒答样本（教会模型说"图里没有"）。质量治理：去重、任务配比、难度分层、答案长度控制、**加入纯文本数据防遗忘**。

### Q24 ★★ 冻结策略怎么选？

**A**：三种常见配置：
- **只训 projector**（最省，适合对齐阶段、大量数据但算力紧）；
- **训 projector + LLM（LoRA 或全参）**（主流，SFT 阶段）；
- **全解冻含视觉塔**（数据量大、领域差异大时才做，学习率要小，否则破坏预训练特征）。

判断依据一句话：**数据量小就多冻结，领域差异大就多解冻**。

### Q25 ★★★ LoRA 是什么？为什么能省显存？

**A**：冻结原权重 W，只学低秩增量 ΔW = B·A，其中 A∈R^{r×d}、B∈R^{d×r}，r 远小于 d，前向是 `h = Wx + (alpha/r)·BAx`。

省显存的原因：**只对 A/B 求梯度、只给它们存优化器状态**（Adam 要 2 份动量，这才是显存大头），可训练参数常降到 0.1%~1%。推理时可以把 BA 加回 W，**零额外延迟**。

参数建议：rank 8~64，alpha 常取 2r，作用于 q/k/v/o 和 MLP 的全部线性层（比只加 q/v 效果好）。追问 **QLoRA**：基座量化到 4bit（NF4）+ 双重量化 + paged optimizer，可在单卡训 65B。

### Q26 ★★★ 训练大模型显存都花在哪？怎么省？

**A**：四块（按大小排，以参数量 P、字节数计）：**参数 2P（fp16）+ 梯度 2P + 优化器状态 12P（Adam fp32 的 m/v/主权重）+ 激活**。前三个是"静态的"，激活随 batch×序列长度线性增长。

省的手段：**ZeRO-1 切优化器状态 / ZeRO-2 再切梯度 / ZeRO-3 再切参数**；**梯度检查点**（重算激活，显存换 30% 时间）；**混合精度 + bf16**（比 fp16 稳，不用 loss scaling）；**梯度累积**（小 batch 模拟大 batch）；**序列并行/FlashAttention**（省激活里的注意力矩阵）；**offload**（CPU/NVMe，慢）。

**你的接口**："我在 8 卡训练集群 上把显存从 约 89GB 压到 约 82GB，方法是用 32×32 混合矩阵替代 3-tap 大核，保住 batch 和分辨率——本质是'算力不变但中间张量变小'的重构思路。"（**这条极其对口，面试官会顺着问下去**）

### Q27 ★★ 训练不稳定 / loss 突然爆掉 / 出 nan，怎么排查？

**A**：按顺序查，别乱猜：
1. **数据侧**：label 越界、空样本、异常值（我遇到的真实案例：CE 的 target 越界，参数名 `cls_num` 与实际类别数不一致，loss 直接崩）；
2. **数值侧**：fp16 溢出 → 换 bf16 或加 loss scaling；attention 里 mask 全 −inf → nan；除零；
3. **学习率**：太大 → 加 warmup、降峰值；梯度裁剪（通常 1.0）；
4. **结构侧**：新加的层初始化不当（用恒等初始化/零门控）；残差尺度；
5. **硬件侧**：CUBLAS workspace 不足、OOM 报错伪装成算子错误（我真遇到过 `CUBLAS_STATUS_ALLOC_FAILED`，根因是超大 batch 的 GEMM workspace，改 depthwise+pool 解决）。

**答法价值**：这段回答的分数在"你怎么定位"，而不是"你修了什么"——按"数据→数值→超参→结构→硬件"的层次说，显得有方法论。

### Q28 ★ 多图/多轮对话在序列里怎么组织？

**A**：图像 token 按出现顺序插在对话流里，用特殊 token 界定每张图的区间；多轮时**历史轮次保留（可能要压缩）**，图像通常只在第一次出现时插入，后续轮引用"上面那张图"。工程上的三个坑：① KV cache 随轮数增长；② 图像 token 太多导致历史被挤掉，需要"图像 token 压缩/丢弃旧图"策略；③ 位置编码要能区分"第几张图"。

### Q29 ★★ 宽高比差异大的图（比如 1920×200 的长条票据）怎么处理？

**A**：固定 resize 会严重失真（OCR 直接废掉）。方案：**按比例切块**（切成若干接近正方形的小块 + 一张缩略图，InternVL/LLaVA-1.6 的做法）；或**pad 到固定比例**；或**原生分辨率 patch 化**（NaViT）。判断标准：下游是否依赖细节（OCR/小目标 → 必须保分辨率）。

### Q30 ★★ 图文 token 比例怎么控制？

**A**：给一个经验量化：**一张 336×336 图约 576 个 token（patch14）或 256 个（patch16 + 池化）**；LLM 上下文 4096 时，一张图能吃掉 1/7。所以工程上要定"每图 token 预算"（如 256/576/1024），按任务分配——OCR/grounding 给多，闲聊给少。视频更极端：**必须做帧采样 + 时序池化**。

### Q31 ★ 模态桥接层选 linear / MLP / Q-Former / Perceiver，怎么选？

**A**：一句话决策表：

| 桥接 | token 是否压缩 | 训练成本 | 什么时候用 |
|---|---|---|---|
| linear | 不压 | 最低 | 极简基线 |
| 2 层 MLP | 不压 | 低 | **主流选择**（LLaVA 系），token 预算宽松 |
| Q-Former | 压到固定数 | 中（多阶段） | token 预算紧、要多任务对齐（BLIP-2） |
| Perceiver | 压到固定数 | 中 | 交错图文、多图（Flamingo） |

### Q32 ★★ 混合模态训练时，模型"忘记"纯文本能力怎么办？

**A**：**数据里保留纯文本数据**（通常是图文数据的一定比例，经验值 10%~30%），并且**图文数据与纯文本数据同 batch 混训**；SFT 阶段尤其要注意，否则模型会退化成"只会描述图像"。评测时同时看纯文本 benchmark，别只看多模态分。

## S4 幻觉、对齐与评测（12 问）

### Q33 ★★★ 多模态大模型的"幻觉"是什么？分几类？

**A**：模型生成了图像中不存在的信息。两类分法（面试用第二种更专业）：
1. **按对象**：物体幻觉（说有不存在的物体）、属性幻觉（颜色/数量错）、关系幻觉（空间关系错）。
2. **按来源**：**语言先验主导型**（沿用训练语料里的常见搭配，无视图像）、**视觉信息缺失型**（图里看不清/没看到，编一个）、**对齐错误型**（看到了但映射错）。

### Q34 ★★★ 幻觉的根因是什么？

**A**：一句话：**语言先验的强度压过了视觉证据**。具体四层：① 训练数据里图文对噪声大，模型学会"不看图也能猜对"；② 自回归目标鼓励"流畅"而非"忠实"；③ 视觉 token 少（分辨率低/被压缩），证据本身就弱；④ SFT 数据里缺少"我不知道/图里没有"的样本。这条根因和 POPE 里 "adversarial" 设置的设计动机直接相关。

### Q35 ★★★ 怎么缓解幻觉？

**A**：按训练流程分四层：
- **数据**：负样本（有图的/没有的）、拒答样本、"不同→对比"样本；提高图文对质量。
- **训练**：加辅助损失（如对比/grounding 监督，强制对齐区域）、视觉 token 加权、加大视觉分辨率。
- **解码**：降低温度、对比解码（VCD，用"加噪图"和"原图"的 logits 差放大视觉贡献）、惩罚高频先验词。
- **后处理/评测**：POPE/HallusionBench 定期体检；RAG 引入外部事实。

**你的接口**：可以类比讲"我在占用预测里做的 fn/fp 成分解剖（no_hit/wrong_cls/early/late）——把错误拆成分项，才知道该改模型还是改标签"。这套方法论迁移到幻觉上就是"把幻觉按类型统计，而不是只看一个总分"。

### Q36 ★★ SFT 数据为什么要"拒绝采样"？

**A**：让强模型对同一问题采样多条回答，用奖励模型/规则/人工筛掉差的，只保留高质量的那条（best-of-n）。好处：把"生成能力"和"筛选能力"解耦——**用贵的模型筛，用便宜的模型学**。这也是蒸馏型 SFT 数据的常见做法。

### Q37 ★★ RLHF 的完整流程？

**A**：三步：① **SFT** 得到初始策略；② **训练奖励模型 RM**（用人类偏好对 (chosen, rejected) 做 Bradley-Terry 二分类）；③ **用 PPO 优化策略**，奖励 = RM 打分 − β·KL(π‖π_ref)（KL 项防止跑偏太远）。多模态里 RM 要吃到图像，所以 RM 本身也是个 VLM。

### Q38 ★★★ DPO 和 PPO 的区别？为什么 DPO 更流行？

**A**：DPO 把"RM + RL"合并成一个**分类式损失**：直接用偏好对 (y_w, y_l) 优化策略，隐含的奖励是 `β·log(π(y|x)/π_ref(y|x))`。

- **PPO**：要单独训 RM、要采样、要 4 个模型（policy/value/ref/RM），工程复杂、易不稳。
- **DPO**：不需要 RM、不需要在线采样，一个 loss、两个模型（policy + ref），稳定且便宜。
- 代价：DPO 是**离线**的，没有在线探索，理论上限低于 PPO/在线方法；数据分布外表现差。

**追问**：GRPO 是什么？→ DeepSeek 系的做法：去掉 value model，对同一个 prompt 采样一组（group）输出，用组内相对优势做基线，省掉 critic 网络，等价于"组内归一化的策略梯度"。

### Q39 ★★★ 多模态评测集都测什么？各举一个必背的。

| 评测集 | 测什么 | 一句必背 |
|---|---|---|
| **MMBench** | 综合能力（20 类能力维度） | 用 CircularEval 消除选项顺序偏差 |
| **MMMU** | 大学水平学科推理（图表、公式、考试题） | 多学科、多图、需要专业知识 |
| **SEED-Bench** | 生成式理解（图像+视频） | 多项选择 + 人工校验 |
| **POPE** | **物体幻觉** | 用"是否存在某物体"的 yes/no 探测幻觉 |
| **HallusionBench** | 幻觉（视觉依赖 + 反事实） | 专测"看图说话 vs 靠先验编" |
| **MM-Vet** | 综合能力（识别+推理+OCR 混合） | 用 GPT-4 打分，能力维度交叉 |
| **RefCOCO/RefCOCO+/gRefCOCO** | 指代定位 grounding | 给文本描述输出框，准确率/IoU |
| **VideoMME / LongVideoBench** | 视频理解（短/中/长，有无字幕） | 长视频显式考察时序与检索 |
| **TextVQA / DocVQA / ChartQA** | OCR 与文档/图表理解 | 工业落地最常用 |

### Q40 ★★ POPE 的三个设置是什么？为什么这么设计？

**A**：**random**（随机选不存在物体）、**popular**（选数据集中高频但图里没有的物体）、**adversarial**（选和图中物体共现频率高、最容易骗过模型的物体）。指标是 Accuracy / Precision / Recall / **F1** 和 yes 比例。设计动机：随机负样本太简单，会上报虚高分数，**adversarial 才是真考验"是否真在看图"**。

### Q41 ★★ MMBench 的 CircularEval 是什么？为什么需要？

**A**：把一道多选题的选项**循环移位多次**，每次让模型回答，只有全部正确才算对。因为 VLM 对选项位置有强烈偏好（比如总选 A/B），不移位会高估能力。这是"评测口径"的经典例子——**面试时讲这个，比背指标更能证明你读过评测细节**。

### Q42 ★★ 评测里常见的坑有哪些？

**A**：五个：① **数据泄漏**（训练集和评测集图像近重复，尤其 CLIP 系预训练数据几乎覆盖全网）；② **prompt 敏感**（换个模板差 5 个点）；③ **选项偏差**（要 CircularEval / 打乱）；④ **指标口径不一致**（BLEU/CIDEr 对生成式评测不可靠，所以现代评测多用 GPT 打分或人工，但 GPT 打分本身有偏差）；⑤ **只报总分不报分项**（真实能力要看分项，比如 OCR 强但推理弱）。

### Q43 ★★ grounding 任务怎么评测？

**A**：输入"图中的白色小狗"，模型输出框或 mask，和 GT 比 **IoU / 点命中**。指标：RefCOCO 用 Acc@0.5（IoU>0.5 的比例），也常用**点级准确率**（输出点落在 GT mask 内的比例，更宽容）。难点：**指代歧义**（多只同类物体）、**否定/关系描述**（"不在桌上的那个"）。

### Q44 ★ 为什么要关心"纯文本能力不退化"？

**A**：多模态模型最终是个 LLM，用户会问纯文本问题。若 SFT 只喂图文数据，模型的语言能力、指令遵循、长文组织都会退化（catastrophic forgetting）。做法：混入纯文本指令数据、评测时同时跑文本 benchmark、必要时用 LoRA 限制参数漂移。

## S5 视频理解与生成（10 问）

### Q45 ★★★ 视频的 token 数量为什么是灾难？怎么压？

**A**：算一下就明白：一帧 224×224/patch16 = 196 token，**32 帧就是 6,272 token**，还没算文本；1 分钟 30fps 有 1800 帧 → 35 万 token。**必须压**。

四条路：① **帧采样**（均匀/关键帧/内容自适应，常见 8~64 帧）；② **空间压缩**（每帧先池化/pixel shuffle）；③ **时间压缩**（相邻帧特征做时序池化、3D VAE、token merge）；④ **分层+检索**（长视频先摘要再检索片段，LongVA/Video-LLaVA 那类）。工程口诀：**"先降帧率，再降分辨率，最后压在时序维上"**。

### Q46 ★★ 视频里的时序信息怎么建模？

**A**：三种主流：① **逐帧独立编码 + 序列拼接**（最简单，靠 LLM 自己学时序，需要时序位置编码区分帧）；② **时空联合 patch**（3D ViT / VideoMAE，把 t 维也切 patch）；③ **时空聚合模块**（在视觉塔里做帧间 attention 或 pooling，输出固定帧数）。位置编码上常用 **3D RoPE（时间+高+宽）**，Qwen2-VL 就是 M-RoPE。

### Q47 ★★ 长视频（1 小时以上）怎么做？

**A**：核心思想是**不要把所有帧塞进上下文**，而是"摘要 + 检索 + 分层"：
1. 关键帧/场景切分（用变化检测或聚类）；
2. 每段单独编码成紧凑描述（caption/embedding）；
3. 提问时先检索相关段（embedding 检索或轻量模型打分），只把相关段的细节 token 送进 LLM；
4. 需要全局理解时用分层摘要（段→章）。

**你的接口**：你的 scene-aligned 时序切分（避免跨场景污染）+ 时序历史缓存控制，和这个"分段+检索"思路同构，可以顺势讲。

### Q48 ★★ 视频理解评测看什么？

**A**：**VideoMME**（短/中/长视频 × 有无字幕，显式暴露长视频退化）、**LongVideoBench**（长上下文）、**MVBench**（时序动作）、**EgoSchema**（第一视角长视频）。关键不是分数而是**分档看**：短视频好、长视频崩，是普遍的现状——所以要报"分时长档"的结果。

### Q49 ★★ 扩散模型的前向和反向过程各是什么？

**A**：
- **前向**（加噪，无参数）：`x_t = √ᾱ_t·x_0 + √(1-ᾱ_t)·ε`，T 步（典型 1000 步）把数据变成纯噪声，马尔可夫链。
- **反向**（去噪，学网络）：训练一个网络 ε_θ(x_t, t) 预测噪声，损失是 `||ε - ε_θ(x_t, t)||²`（也可以是预测 x_0 或 v）。采样时从纯噪声逐步去噪。

一句话本质：**扩散模型 = 学一个"从噪声回到数据"的分数函数（score）**。

### Q50 ★★ DDPM 和 DDIM 的区别？

**A**：DDPM 的反向是**随机**马尔可夫过程（每步加噪），要 1000 步；DDIM 构造一个**确定性**（或可控随机）的非马尔可夫采样过程，**可以用 20~50 步得到近似结果**，且同一噪声种子结果可复现。后来的 DPM-Solver、uniPC 把它做成 ODE 求解器，10 步左右就够。**工程意义：采样步数是生图/生视频的延迟主因**。

### Q51 ★★★ CFG（Classifier-Free Guidance）是什么？

**A**：训练时把条件（文本）以一定概率置空，让同一个网络同时学"有条件"和"无条件"；采样时把两者外推：
```text
ε = ε_uncond + s·(ε_cond − ε_uncond)
```
`s` 就是 guidance scale（常用 5~9）。**s 大 → 更贴合文本但多样性下降、易过饱和；s=1 → 等于纯条件采样。**

**追问**：为什么叫 classifier-free？→ 早期用单独训的分类器梯度做引导（Classifier Guidance），后来改成同一个网络的条件/无条件差，不需要分类器。

### Q52 ★★ Latent Diffusion（Stable Diffusion）的关键设计？

**A**：不在像素空间扩散，而是先用 VAE 把图压到**低维 latent**（如 512×512×3 → 64×64×4，压缩 48 倍），在 latent 上做扩散，最后 VAE 解码回像素。好处：算力下降一个量级以上，让消费级卡能训。代价：VAE 是瓶颈（细节/文字渲染差，所以后来的 SD3/Flux 改 VAE 或换架构）。条件注入用 **cross-attention**（文本 token 作为 K/V）——**这里和 LLM 的多模态融合是同一个机制，可以顺势讲**。

### Q53 ★ DiT 是什么？统一理解与生成为什么难？

**A**：DiT 把扩散的 U-Net 换成 **Transformer**（patch 化 + adaLN 注入时间/条件），scaling 行为更好，是 SD3/Flux/Sora 系的基础。统一模型的难点：**理解要判别式语义特征，生成要像素级重建细节**，两者目标冲突；路线有"共享 Transformer + 不同 head"（Transfusion、Emu3 用离散 token 统一）、"生成用扩散头、理解用 LM 头"。目前没有公认最优解——**答"这是开放问题"比硬编答案好**。

### Q54 ★★ 视频生成比图像生成难在哪？

**A**：四条：① **时序一致性**（闪烁、形变、物体消失）；② **数据**（高质量视频+文本对远少于图像）；③ **算力/显存**（3D VAE + 时空注意力，长度线性涨）；④ **运动可控性**（镜头运动 vs 物体运动要分开控制，常用轨迹/光流/相机参数条件）。工程上还有"首尾帧控制、参考图一致性"这类产品化需求。

## S6 推理部署与工程（10 问）

### Q55 ★★★ 推理时 KV cache 怎么算？为什么它是瓶颈？

**A**：每层每个 token 要缓存 K 和 V：
```text
显存 ≈ 2 × n_layers × n_kv_heads × d_head × seq_len × batch × 精度字节
```
例：32 层、32 头、d_head=128、fp16、seq 2048、batch 1 → 2×32×32×128×2048×2 ≈ **1.07 GB**，batch 和长度都线性叠上去。

它是瓶颈的原因：**decode 阶段每一步都要读一遍整个 cache**，是**访存密集**而不是计算密集，所以长上下文时 GPU 利用率很低。解法：GQA/MQA（`n_kv_heads` 变小）、KV 量化（INT8/INT4）、PagedAttention（消除碎片）、滑动窗口/丢弃远距离、prefix cache 复用。

### Q56 ★★★ Prefill 和 Decode 两个阶段的差异？

**A**：

| | Prefill（读 prompt） | Decode（逐 token 生成） |
|---|---|---|
| 并行度 | 整段并行，**计算密集**（大 GEMM） | 每步 1 个 token，**访存密集** |
| 瓶颈 | 算力 / FLOPS | HBM 带宽（要读全部权重+KV cache） |
| 优化 | FlashAttention、大 batch、融合算子 | KV cache 压缩、投机解码、连续批处理、量化 |

**面试价值**："端侧延迟主要花在 prefill（图 token 多）还是 decode（输出长）要分开看"——这句话能立刻显出你有实测概念。**你的真实数据**：MDC610 上做算子解耦+向量化把误检从 约 5% 降到约 1.4%，可以顺势讲"我做过 prefill 侧（视觉塔+投影）的算子级优化"。

### Q57 ★★ PagedAttention / vLLM 解决什么问题？

**A**：传统实现给每个请求预分配连续 KV 显存，长度未知导致**大量碎片和浪费（实测浪费可到 60%+）**。PagedAttention 把 KV cache 切成固定大小的 block，用页表映射，**按需分配、可共享（同一 prompt 的多个采样共享前缀）**，配合 **continuous batching**（请求完成就换新请求进 batch，不等最慢的）把吞吐提升数倍。

### Q58 ★★ 投机解码（speculative decoding）是什么？

**A**：用一个小模型（或 n-gram/检索）先草拟 k 个 token，大模型**并行验证**这 k 个，接受前缀匹配的部分、拒绝第一个不匹配处。因为验证是并行的（一次 forward 出 k 个位置的 logits），**在不改变输出分布的前提下加速**（严格等价，这是它的理论保证）。典型加速 1.5~3×，取决于草稿命中率。

### Q59 ★★ 量化怎么选？INT8 / INT4 各有什么代价？

**A**：权重 INT8 基本无损（W8A8/W8A16 常用）；**INT4 权重会出现明显精度损失**，需要算法补偿：**GPTQ**（逐层量化 + Hessian 补偿）、**AWQ**（保护重要通道，激活感知）、**SmoothQuant**（把激活的难度迁到权重上）。还有 KV cache 量化（长上下文更划算）。判断标准：先看任务对长尾/数值敏感的程度（OCR、数学推理对量化更敏感）。

### Q60 ★★ 蒸馏在多模态里怎么做？

**A**：三条路：① **logit 蒸馏**（学生对齐教师的输出分布，加温度 T）；② **特征蒸馏**（对齐中间层/token 表示，多模态常用"对齐教师看同一张图后的视觉 embedding"）；③ **数据蒸馏**（用教师生成的问答对训学生，最常用、最省事）。端侧落地常见组合：**小视觉塔 + 小 LLM + 教师蒸馏数据 + 量化**。

### Q61 ★★ 端侧多模态模型最难的三件事？

**A**：
1. **分辨率 vs 算力**：端侧要看清（OCR/小目标）就得高分辨率，而分辨率直接变成 token 和算力——这是根本矛盾。
2. **显存/内存**：手机/车机的可用内存是 GB 级，KV cache + 权重 + 激活都要算进去。
3. **算子与后端**：不是所有算子都能落到 NPU/GPU（attention 的动态形状、动态分辨率、nms/topk），要**改写算子或换等价语义**。

**你的接口**（这是你最强的差异化）："我在 MDC610 上做过完整的 ONNX→ATC/AOE→`.om` 链路，对不支持算子做了解耦 + OpenCV 向量化重写，端侧误检 约 5%→约 1.4%。所以端侧多模态我也会先问三个问题：**目标 SoC 的算子白名单、内存预算、以及是否允许动态分辨率**。"

### Q62 ★★★ 昇腾（Ascend）生态你了解多少？——**送分题，必须答满**

**A**：分层说：
- **硬件**：Ascend 310/910B（推理/训练），达芬奇架构（Cube 矩阵单元 + Vector 单元）。
- **软件栈**：**CANN**（异构计算架构，对标 CUDA）→ **ATC**（模型转换：ONNX/PB → `.om` 离线模型）→ **AOE**（自动调优，选 tiling/算子实现）→ **AscendCL**（推理 API）。
- **框架**：**MindSpore**（自研）/ PyTorch 通过 torch_npu 适配。
- **工程坑**：算子不支持要拆或替换；动态 shape 支持有限，常需分档固定 shape；精度对齐要做（fp16 溢出、算子融合顺序差异）；内存要手工规划（模型/工作空间）。

**话术**："我做过完整的 ONNX(opset11/16)→ATC/AOE→MDC610 `.om` 落地，对 AscendCL 的输入输出 binding、内存对齐、算子不支持时的等价改写都有实操。"→ **这是华为面试里最能加分的一段，因为大部分算法候选人只会写 train.py。**

### Q63 ★ 端侧时延怎么拆？怎么定位瓶颈？

**A**：拆成四段并分别打点：**① 预处理**（resize/归一化/拼接，CPU 上很贵，别忽略）→ **② 视觉塔**（ViT 前向，可用 batch/半精度）→ **③ projector + prefill**（LLM 一次前向处理所有图文 token）→ **④ decode**（每 token 一次，按输出长度线性）。

定位方法：先测各段独立耗时 + 用 nsys/推理框架的 profile 看算子占比；常见结论是 **prefill 被图像 token 拖累、decode 被 KV cache 带宽拖累、预处理被 Python/CPU 拷贝拖累（用 pinnedMemory/零拷贝可省几十毫秒）**。

### Q64 ★ 多模态推理服务的吞吐怎么提？

**A**：五个手段：① **统一 batch 内的 shape**（动态分辨率会让 batch 里 shape 不一，要么 padding 要么分桶）；② **连续批处理**（不等最长序列）；③ **prefix/图像特征缓存**（同一张图多轮问答，视觉塔的结果缓存重用，这是多模态特有的收益）；④ **量化 + 投机解码**；⑤ **视觉塔与 LLM 异构并行**（视觉塔放另一张卡/另一个流，与 decode 重叠）。

## S7 把你的项目接进多模态叙事 + 临场策略（10 问）

### Q65 ★★★ 「你做的是感知，凭什么做多模态大模型？」怎么答？

**A**：三段式，**不要说"我可以学"**：
1. **做过的同构问题**："我做的视觉+激光融合本质是跨模态对齐：两种异构传感器（图像是稠密透视、激光是稀疏度量）在统一 BEV 网格上做门控融合，处理的核心难点和 VLM 里的图文对齐同源——**都是把不同分布、不同粒度的表征映射到一个可比较的空间**。"
2. **可迁移的工程能力**："大规模训练调优（8 卡训练集群、显存墙下的结构重构、loss 崩溃的三连排查）、数据生产线与评测口径（25 万场景/百万关键帧、双 seed 噪声地板）、端侧部署（ONNX→ATC→MDC610）。这三件事恰好是 VLM 落地最缺的能力——**模型结构论文里都有，但数据、训练稳定性、部署是真功夫**。"
3. **明确承认缺口 + 已做的补课**："VLM 的 SFT/偏好对齐我没在生产里做过，所以我按 LLaVA 两阶段在自己的数据上复现过、也读了 Qwen-VL/InternVL 的报告，重点看它们的 token 压缩和数据配比。"

### Q66 ★★★ 你的视觉-激光融合 vs 多模态的 cross-attention，有什么关系？

**A**："我的融合是**结构化的跨模态交互**：两路特征在 BEV 网格上对齐后，用 SE 通道门控做重加权，再由卷积融合。VLM 里的 cross-attention 是**用注意力动态决定'从另一模态取什么'**，表达力更强但计算更贵（O(N²)）。

如果让我改造，我会把静态门控换成 **query-based cross-attention**：BEV query 作 Q、图像特征作 K/V，这样融合权重是按位置和内容动态生成的——**这正好是 BEVFormer 和 Flamingo/Q-Former 的共同思路**。"

（**这段是全场最高分的回答，把两个领域用同一个机制连起来了**）

### Q67 ★★ 你的 BEV query 和 Q-Former 的 query 是一回事吗？

**A**："形式上同类：都是**固定数量、可学习、通过 cross-attention 从高冗余输入里抽信息**。差别在约束：BEV query 有**强几何先验**（每个 query 对应一个固定的世界坐标格子，靠相机内外参做投影），所以 token 的位置是"物理正确"的；Q-Former 的 query 没有几何约束，纯靠数据学。

前者适合需要**度量精度**的任务（占用、检测），后者适合**语义检索**（"图里有什么"）。如果要给 VLM 加空间精度，用带几何先验的 query（3D grounding、SpatialVLM 一类工作）是自然方向。"

### Q68 ★★ 你的时序建模经验怎么迁移到视频多模态？

**A**："我做过两件相关的事：按 scene 对齐切时序段（避免跨场景污染）、维护时序历史缓存（在 mIoU 与显存之间做权衡）。换成视频理解，对应的问题是**帧采样策略**和**历史 token 预算**：帧采样的关键是'别把同一场景的冗余帧重复喂进去'，历史 token 的关键是'压缩方式要与任务相关'——我倾向于先做场景切分 + 关键帧，再做时序池化，这和我在 OCC 上的做法同构。"

### Q69 ★★ 数据生产线经验怎么讲成 VLM 的加分项？

**A**："多模态模型的上限基本由数据决定，而我在'数据-评测-归因'这条链上有完整实操：① **大规模生产**（数万个场景 / 百万级关键帧，含三态标注）；② **口径治理**（发现过转换器两个方向相反的 filter 版本导致 mask 体积只有 约 0.64 倍、mIoU 降约 3 个点 的隐性 bug，用逐元素对比 + IoU=1.0 锁定）；③ **评测设计**（万级帧协议 + 双 seed 噪声地板，把'模型变好'和'评测抖动'分开）。

迁到 VLM：数据配比、去重、caption 重写、幻觉负样本构造、以及'分项评测而不是只看总分'，方法论完全一致。"

### Q70 ★★ 端侧部署经验怎么讲？

**A**：见 Q61/Q62。核心三句：**ONNX→ATC/AOE→`.om` 全链路实操过；不支持算子做等价改写（Decode/TopK/NMS 解耦 + OpenCV 向量化）；有实测指标（ROI 超分误检 约 5%→约 1.4%）。**

### Q71 ★ 具身智能 / VLA / 空间智能你了解吗？

**A**：一句话版：**VLA = 视觉语言模型 + 动作输出头**（RT-2、OpenVLA、π0 这类），把"看图 + 听指令 → 输出动作 token/轨迹"。关键难点：动作数据的稀缺与异构（不同机器人本体）、实时性（要 10~100Hz 控制频率）、空间精度（需要 3D 表征而不是 2D token）。

**你的优势**：**你是所有候选人里少数真做过 3D 几何、占有栅格、标定的人**——"具身落地最缺的就是 3D 空间理解与传感器标定，这两块是我的强项"。这句话会让面试官记住你。

### Q72 ★★★ 遇到完全不会的问题怎么答？（临场策略，价值极高）

**A**：三步，别硬编：
1. **确认范围**："您问的是训练侧还是推理侧？"（把开放问题变窄，争取思考时间）；
2. **给出你确定的相邻知识**："这块我没在生产里做过，但我知道它的相邻问题是这样解决的……"（展示知识网而不是空白）；

## S8 多模态融合的调控（雷达 / 激光 + 图像）

> 这一章是**技术专章**：把"融合"从一句口号拆成**六个可以分别调、分别验证的旋钮**。面试官问"你们怎么融合的"，能按这六个旋钮回答，就已经超过 90% 的候选人。

### 融合调控的六个旋钮（总览）

| 旋钮 | 要决定什么 | 出问题时的症状 |
|---|---|---|
| ① **在哪融**（层级/位置） | 数据级 / 特征级 / 决策级；backbone 前 / 中 / 后；图像平面 or BEV 空间 | 融合后反而比单模态差 |
| ② **拿什么融**（表征） | raw point / BEV 特征 / 体素 / object proposal / occupancy | 信息被稀释，或两路高度冗余 |
| ③ **怎么配权**（权重） | 静态可学习权重 / 动态门控 / 不确定性加权 / 可靠性路由 | 一路主导，另一路"形同虚设" |
| ④ **怎么对齐**（坐标与时间） | 标定精度 / 时间戳选择 / 自车运动补偿 / 尺度匹配 | 融合出现鬼影、错位、拖影 |
| ⑤ **怎么防退化**（训练策略） | 模态 dropout / 失效增广 / 融合层 warmup / 梯度平衡 | 雨天、夜间、镜头污损就崩 |
| ⑥ **怎么证明**（评测归因） | 单模态基线 / 模态消融 / 门控可视化 / 逐类逐距归因 | 说不清融合到底贡献了什么 |

**一句话心法**：融合不是"把两个特征拼起来"，而是**先回答"这两个模态在什么空间、以什么权重、在什么条件下可信"三个问题**。

### Q75 ★★★ 融合有哪几个层级？各自适合什么任务？

**A**：三层 + 一个混合式：

| 层级 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **数据级**（早期） | 点云投影到图像取 ROI，或图像反投影成点带颜色 | 简单、直观、信息最原始 | 强依赖标定精度；破坏点云几何结构；投影后稀疏 |
| **特征级**（中期，**主流**） | 两路各自编码成 BEV 特征 / 体素特征，在统一网格上融合 | 保住几何、可端到端、表达力强 | 需要空间对齐；计算量最大 |
| **决策级**（晚期） | 各自出检测框，再做关联（匈牙利匹配）与置信度融合 | 鲁棒、可解释、模块可替换 | 丢细粒度信息，早融合的增益拿不到 |
| **混合式** | 训练时用单模态辅助头做蒸馏，推理只走融合 | 兼顾收敛与精度 | 实现复杂 |

**面试答法**："我们走的是特征级、在 BEV 空间融合——因为感知任务要的是**度量精度**，图像平面上的融合丢了深度和尺度；决策级虽然鲁棒但拿不到'用激光的几何去校正视觉的语义'这种细粒度收益。"

**追问**：为什么 BEV 是融合的"公共语言"？→ 因为它是唯一同时满足"有度量、可向各传感器投影、能承载时序"的空间。相机靠深度估计投上去，激光/雷达靠标定投上去。

### Q76 ★★★ 相机、激光雷达、毫米波雷达三者的特性怎么互补？

**A**：面试必备表格：

| 维度 | 相机 | 激光雷达（LiDAR） | 毫米波雷达（Radar） |
|---|---|---|---|
| 数据类型 | 稠密透视图像 | 稠密 3D 点（万~十万级） | 极稀疏 3D+速度（千~万级） |
| 语义/纹理 | **最强**（颜色、文字、细分类） | 弱（反射强度） | 几乎无 |
| 几何精度 | 间接（靠深度估计） | **最强**（cm 级测距） | 中等（角分辨率差，距离准） |
| 速度测量 | 需多帧估计 | 需多帧估计 | **直接测速**（多普勒） |
| 恶劣天气 | 差（雨雾、逆光、夜间） | 差（雨雾散射、衰减） | **最强**（穿透雨雾尘） |
| 成本 | 低 | 高（机械式尤甚） | **最低** |
| 高度信息 | 有（透视） | 有 | 传统雷达弱（4D 成像雷达才补上俯仰） |

**一句话总结**："相机给语义、激光给几何、雷达给全天候和速度——**融合的本质是让某一路的短板刚好被另一路覆盖**。"

**追问**：既然雷达全天候，为什么不只用雷达？→ 稀疏 + 角分辨率低 + 无类别语义，必须靠视觉补语义、靠激光补几何。

### Q77 ★★ 毫米波雷达-图像融合 和 激光雷达-图像融合，做法有什么区别？

**A**：差别来自**数据密度和信息维度**：

| | 激光-图像 | 毫米波雷达-图像 |
|---|---|---|
| 点密度 | 万~十万级 | 千~万级（4D 成像雷达可达数万） |
| 融合前提 | 可体素化/BEV 稠密化后卷积 | **不能直接稠密化**（太稀疏，卷积核被空洞稀释） |
| 主流做法 | BEV 特征 concat + 门控 / cross-attention | **pillar 化 + 稀疏卷积**，或**点级 query**，或**先多帧累积再加稠密** |
| 独有信息 | 高度、精确轮廓 | **多普勒速度通道**（单独当一路特征）、RCS 强度 |
| 时序依赖 | 中等 | **强**（单帧点太少，几乎必须累积多帧） |
| 对齐难点 | 标定精度、稀疏投影空洞 | **角分辨率差**（远处方位误差大）、多径杂波 |

**关键差异一句话**："激光可以'先稠密化再卷积'，雷达不行——雷达必须**先累积时序、再用稀疏算子**，否则融合模块学到的主要是空洞。"

**追问**：多普勒速度怎么用？→ 三种用法：① 作为额外通道拼进点特征；② 用来做**静止点剔除/自车速度估计**（点云配准的前置）；③ 作为独立的一路"速度图"（BEV 上按距离环统计），和图像的车道/语义特征交叉验证。

### Q78 ★★★ 特征级融合有哪四种典型结构？各自代价？

**A**：

1. **Concat + 卷积**（基线）：`f = Conv([f_img ; f_lidar])`。最便宜，但**没有配权能力**，容易一路主导。
2. **门控/注意力加权**：`f = g⊙f_img + (1−g)⊙f_lidar`，`g` 由 sigmoid 产生（SE / CBAM / per-pixel gate / FiLM）。**性价比最高**，工业界主流。
3. **Cross-attention**：一个模态作 Q、另一个作 K/V，做非对称的"查询—取用"。表达力最强，代价 O(N²)，需要 mask（视锥裁切）。
4. **MoE / 混合专家**：多个融合专家 + 路由网络，按场景（高速/城区/地库）分配。参数量涨、路由可能退化（负载不均）。

**选择口诀**：**算力紧、模态稳定 → 门控；需要细粒度互查 → attention；场景类型差异大 → MoE；先有 concat 基线再往上加**。

### Q79 ★★★ 门控具体怎么设计？（这是"调控融合"最核心的一块）

**A**：四种门控，从粗到细：

```text
① SE（通道级）:  z = GAP(f) → FC → FC → σ → 乘回每个通道
② CBAM（通道+空间）: SE 之后接一个 7×7 卷积出空间注意力图
③ per-pixel gate（逐位置）: g = σ(Conv1x1(f))，f = g⊙f_a + (1−g)⊙f_b
④ FiLM（条件调制）: 用一路特征生成 γ,β，去调制另一路:  f_a' = γ⊙f_a + β
```

**三个必须讲的实现细节**：

- **门控初始化**：把最后卷积的 bias 初始化成较大正值（如 4.0），使 sigmoid ≈ 1，融合层初始化时**近似恒等**，不破坏预训练分支。这就是 Flamingo 的 gated cross-attention 思想（用 `tanh` 门控 + 零初始化）。
- **别让门控退化成常数**：如果门控对几乎所有输入都输出 0.5，等于静态加权。检查手段：打印门控值的直方图与空间分布。
- **跨模态归一化**：两路特征的均值方差往往差一个量级（激光强度分布 vs 图像 BN 后分布），直接 concat 会让一路吃满梯度。做法：**每路一个 modality-specific BN，融合前再统一 LayerNorm**。这一步经常比换融合结构更有效。

**追问**：为什么 per-pixel gate 比 SE 好？→ SE 只有通道维度，无法表达"近处信激光、远处信相机"这种空间依赖；per-pixel 加空间维，代价只是几个 1×1 卷积。

### Q80 ★★ 用 cross-attention 做融合时，Q/K/V 怎么分配？为什么？

**A**：**Q 来自"目标空间"，K/V 来自"信息源"**。三种分配：

| 配置 | Q | K/V | 用途 |
|---|---|---|---|
| BEV query ← 图像 | BEV 网格（固定数量、有几何坐标） | 多视角图像特征 | 主流：几何可解释、token 数可控（BEVFormer 式） |
| 图像 query ← 雷达/激光 | 图像 patch | 点云/雷达 BEV 特征 | 图像侧增强（加深度/遮挡信息） |
| 双向 | 互相 | 互相 | co-attention，表达力强但双倍代价 |

**为什么 BEV query 作 Q 更好**：① query 数与分辨率解耦，可压缩到预算内；② 每个 query 有明确世界坐标，**位置编码可以直接用 3D 坐标**（不是学出来的）；③ 视锥 mask 天然可算——把不在任何相机视锥内的 query 屏蔽掉，避免"用不存在的观测去猜"。

**追问**：mask 怎么做？→ 用内外参把每个 BEV query 投到每个相机，判断是否落在图像有效区域内且深度为正；对不可见的 (query, camera) 对屏蔽。

### Q81 ★★ 稀疏模态（雷达/点云）怎么进融合网络？

**A**：四条路，按数据密度选：

1. **体素/pillar 化 + 稀疏卷积**：只在实际有点的体素上计算，空洞不参与。适合激光（万级点）和 4D 雷达。
2. **稠密化（Pixor 式）**：把 z 维折进通道，压成 BEV 图。简单，但点少时 99% 是零，卷积核被稀释。
3. **点级 query**：把每个点当 token 做 attention（Point Transformer 式）。表达力强，点数多时贵。
4. **先时序累积再稠密化**：雷达专用——累积 5~10 帧把点密度提上来，再进 BEV 卷积。

**关键工程点**：如果坚持稠密化，**必须加"占用 mask + 归一化"**——只在有观测的位置计算卷积响应，否则学出来的是"哪里有空洞"而不是"哪里有目标"。

### Q82 ★★ 什么时候用"轻量调制"（FiLM/MoE/标量权重）而不是 attention？

**A**：一个判断表：

| 情况 | 推荐 | 理由 |
|---|---|---|
| 模态可靠性稳定、算力紧 | 门控 / FiLM | 参数少、几乎不加延迟 |
| 两路特征语义已对齐，只需"调强弱" | 标量或通道权重 | attention 属于杀鸡用牛刀 |
| 需要"按位置取信息"（如遮挡区） | per-pixel gate / attention | 空间级交互必须有权重图 |
| 场景类型差异极大 | MoE | 路由能按场景切换专家 |
| 端侧部署 | **FiLM / 门控** | attention 的动态 shape 在 NPU 上难落地 |

**端侧那句话（对你特别有用）**："端侧我优先选能静态展开的融合（门控/FiLM），因为 attention 的动态 shape 和 gather 在 NPU 上要么不支持、要么要拆算子。"

### Q83 ★★★ 模态权重怎么调控？四类方法怎么选？

**A**：四类，从"不学到强先验"：

1. **静态可学习标量**：`f = w₁·f_a + w₂·f_b`，`w` 经 softmax 归一化。最简单，但全场景一个权重。
2. **动态门控（内容相关）**：`w = σ(MLP([f_a, f_b]))`，逐位置/逐通道。主流。
3. **不确定性加权**：每个模态学一个观测噪声 σ，权重自动变成 `1/(2σ²)`（详见 Q84）。适合"某模态在某条件下整体不可靠"。
4. **可靠性路由（外部信号驱动）**：用**非学习信号**调权重——能见度/雨量、雷达点云密度与 RCS 分布、图像清晰度（拉普拉斯方差）、激光回波强度统计。规则可写死，也可作为门控的额外输入。

**选型**：`动态门控` 打底（解决空间/内容差异）+ `可靠性路由` 兜底（解决天气/失效这类学习难以泛化的情况）。**两者叠加是工业界常见组合**。

**追问**：为什么不能只靠学习？→ 雨雾、镜头污损这类分布外条件在训练集里占比低，模型学不到"该降权"，必须用先验规则兜住。

### Q84 ★★★ 不确定性加权怎么推导？

**A**：Kendall 多任务不确定性加权，假设每个模态的预测服从高斯，噪声为 σ：

```text
L = Σ_i [ (1/2σ_i²)·L_i + log σ_i ]
```

- `L_i` 是第 i 个模态（或任务）的损失；`log σ_i` 是正则项，防止 σ 无限增大（否则模型靠"说自己不准"来逃避损失）。
- 直观理解：**σ 大 → 该模态权重大幅下降**；但 `log σ` 罚它不能太躺平。
- 实现：把 `log σ²` 作为可学习参数（**不是 σ 本身**，避免除零和负值），用 `exp(-log σ²) · L + log σ²` 计算。
- 坑：① 需要对 `log σ²` 做 clamp（如 [-6, 6]）；② 初始化 0；③ 与门控不同——它是**全局标量**，表达不了"近处信激光、远处信相机"。

**一句话区分**：**不确定性加权调"整体信谁"，门控调"每个位置信谁"**。两者可以叠：门控输出再乘上不确定性权重。

### Q85 ★★ 退化/失效感知的融合怎么做？（雨天、夜间、镜头污损、外参漂移）

**A**：分四类信号 + 四类响应：

| 失效类型 | 可检测信号 | 响应策略 |
|---|---|---|
| 光照/能见度差 | 图像平均亮度、对比度、梯度能量 | 降图像权重、升雷达权重（规则门控） |
| 雨雾对激光衰减 | 点数骤降、远距离回波缺失、强度分布右移 | 降激光权重、缩短有效距离、改用近场几何 |
| 镜头污损/遮挡 | 局部拉普拉斯方差低 + 固定位置模糊块 | 屏蔽该相机、靠其他视角补 |
| 外参漂移 | 跨模态投影残差变大、对齐一致性下降 | 在线标定（路面/杆状物拟合）、降权该视角 |

**做法要点**：把上述信号做成一个**小的可靠性向量**（4~6 维），拼进融合门控的输入——这样"学习 + 规则"结合，既有泛化又能覆盖长尾。

**追问**：外参漂移怎么在线估？→ 用图像上可检测的结构（车道线、杆、路沿）与点云/雷达的对应关系，做小自由度优化（4-DOF：yaw + 3 平移），用残差监控；失败就退回离线标定值。

### Q86 ★★ 门控学歪了怎么发现、怎么纠？

**A**：三个诊断 + 三个纠正：

**诊断**：
1. **门控值直方图**：若集中在 0.5 附近 → 退化成静态权重；若恒为 0 或 1 → 学成了硬选择（可能是对的，也可能一路被忽略）。
2. **空间分布**：画出"近处 vs 远处"、"晴天 vs 雨天" 的平均门控值，看是否符合物理直觉（远处应更信雷达/激光的几何？其实远处激光返点少，应更信相机语义 + 雷达速度）。
3. **单模态消融**：推理时把某一路置零看掉多少分。**掉分很少 = 这一路没被用上**。

**纠正**：
1. **模态 dropout**（Q91）：训练时随机屏蔽一路，强制模型学会两条通路。
2. **辅助单模态损失**：训练时给每路各加一个轻量预测头（推理丢弃），保证每路特征都有判别力。
3. **门控初始化偏置 + 正则**：把门控初始化到接近 1（恒等），再让它学下降；必要时加"门控方差正则"惩罚常数门控。

**面试话术**："我判断融合是否真的生效，不看总分，看**模态消融的掉分幅度**和**门控值的空间分布**——如果屏蔽一路几乎不掉分，说明这一路在偷懒。"

### Q87 ★★★ 空间对齐有哪些坑？（融合失败最常见的根因）

**A**：六个坑，按踩中概率排：

1. **外参角度误差被距离放大**：1° 的旋转误差在 50m 处约 **0.87m** 横向偏移。所以远距离目标的"错位"往往是标定问题，不是模型问题。
2. **时间不同步放大空间误差**：100km/h 下 50ms 的时间差 ≈ **1.4m** 位移。**这是"融合鬼影"的头号原因**，比标定更常见。
3. **视锥裁切缺失**：把投影到图像外的点当成有效观测 → 污染背景。必须按内外参 + 图像尺寸 + 深度>0 三重条件裁。
4. **畸变未校正**：广角/鱼眼相机不做去畸变，边缘区域偏差可达数十像素。
5. **自车运动未补偿**：多帧点云/雷达累积时，不做 ego-motion 变换会出现"拖影"。
6. **网格分辨率与角分辨率不匹配**：BEV 0.6m/格 vs 雷达 1° 方位分辨率（50m ≈ 0.87m），远处一个格子里塞进好几个雷达量测方向。

**一句话**："融合精度上限 = 对齐精度上限。所以我会先做'投影可视化 + 残差统计'这一步，确认对齐没问题再调模型。"

### Q88 ★★★ 时间对齐怎么做？（异步传感器的核心工程）

**A**：四步：

1. **统一时间基准**：所有传感器用**硬件同步时间戳**（PTP/GPS 秒脉冲），不要用主机接收时间（差几十 ms 且抖动大）。这是第一步也是最容易被忽略的一步。
2. **选参考帧**：一般以视觉帧为参考（频率最高、语义最强），把雷达/激光量测通过 **ego-motion** 变换到该时刻。
   ```text
   p_ref = T_ego(Δt) · T_ext · p_sensor
   ```
   Δt 来自时间戳差，`T_ego` 用 IMU/轮速/里程计积分（或用上一帧位姿 + 速度模型近似）。
3. **插值与累积**：雷达 10~20Hz、相机 30Hz，通常不插值（雷达点插值没有物理意义），而是**取最近帧 + 多帧累积**；激光可做运动补偿去畸变（按点时间戳逐点变换）。
4. **验证**：用静止目标（杆、墙、停车车辆）做残差检查——静止目标在多帧融合后应该是"一个点"而不是"一条线"。

**追问**：时间戳经常差几十 ms 怎么办？→ ① 先查是否用了软件时间（改硬件同步）；② 用路面/静止结构做在线时延估计（扫一个 Δt 范围让对齐残差最小）。

### Q89 ★★ 尺度/分辨率失配怎么处理？

**A**：三种手段：

- **模糊化对齐**：把高分辨率一路先做高斯/平均池化到低分辨率再融合（避免"锐利的一路压过模糊的一路"）。
- **由粗到细**：先低分辨率融合（稳定），再用高分辨率特征做精修（detail refinement）。
- **多尺度金字塔融合**：在 2~3 个尺度上分别融合（类似 FPN 的双向融合）。

**注意**：不要指望一个融合模块同时处理不同尺度——**尺度差 2 倍以上时，同一组卷积核的感受野语义就不一样了**，必须分开融。

### Q90 ★★ 跨模态一致性损失怎么加？

**A**：三种，从易到难：

1. **单模态辅助头**（最简单）：每路特征各接一个轻量预测头，训练时算损失、推理丢弃。作用是**保证每路特征都有判别力**，避免一路退化成"旁路"。
2. **一致性正则**：两路各自出预测，让它们互相一致（KL / L2 / 预测级蒸馏），或让融合输出同时逼近两路（防融合"两头不靠"）。
3. **跨模态对比**（最重）：同一目标的图像特征与雷达/激光特征在共享空间拉近，不同目标推远（InfoNCE）。需要目标级对应关系，标注成本高。

**注意坑**：一致性损失太强会让两路趋同、失去互补性（"融合两个一样的模态"）。实践中给个小权重（0.1~0.3）并监控"两路特征相似度"。

### Q91 ★★★ 模态 dropout / 传感器失效增广怎么做？

**A**：这是"防退化"里性价比最高的一招。

- **模态 dropout**：训练时以概率 `p` 把整路输入置零（或替换成可学习的 "missing embedding"，比置零更好）。建议 `p = 0.1~0.3`，**单模态预热之后再开**，否则早期训练太不稳定。
- **关键细节**：置零时**同步跳过融合层的对应权重、并保持归一化统计**——否则 BN/LN 的统计量会被污染，推理时对不上。
- **失效增广**（模拟真实传感器退化）：
  - 点云：随机丢弃远处点（模拟衰减）、按距离衰减点数、加高斯噪声
  - 雷达：随机丢点、加多径杂波
  - 图像：模糊、亮度/对比度扰动、随机遮挡块（模拟污损）、JPEG 压缩
  - 外参：±0.3°~0.5° 随机微扰（模拟标定漂移）
- **训练目标**：让"任意单模态 + 任意退化程度"都有可接受的下限表现，而不是只在"两路都完美"时最好。

**面试话术**："我们不追求实验室里的峰值，而是要保证雨天、夜晚、镜头被泥糊住时还有兜底——所以模态 dropout 和失效增广是标配，模型要为'某只眼睛瞎了'做好训练。"

### Q92 ★★ 融合层怎么 warmup？渐进训练怎么排？

**A**：三步走：

1. **单模态预热**：先让每一路分支单独训到可用（不要一开始就开融合，否则随机初始化的融合层会打断两路的学习）。
2. **零初始化融合**：融合层的输出投影/sigmoid 偏置初始化为"恒等"（输出≈原特征），这样开融合的瞬间不改变原有行为，然后逐步学出增益。
3. **分层学习率**：新加的融合层用较大 lr，预训练分支用较小 lr（1/10）；必要时先冻结分支只训融合，再联合微调。

**追问**：怎么判断 warmup 够了？→ 看"单模态 loss 是否已进入平台期"和"融合后 loss 是否立刻上扬"（上扬说明融合层初始化太激进）。

### Q93 ★★ 两路梯度失衡怎么办？

**A**：症状：某一路的梯度范数小一个数量级 → 该路学不动 → 最终被忽略。

四个手段：
1. **模态特定归一化**（先做这个，成本最低）：每路独立 BN/LN，让两路输出尺度可比，梯度量级自然接近。
2. **学习率分组**：给梯度小的那一路更大的 lr。
3. **GradNorm**：按各任务的梯度范数与收敛速度动态调整权重，让它们同步收敛。
4. **PCGrad（梯度手术）**：当两路梯度方向冲突（余弦相似度为负）时，把冲突分量投影掉。

**实测建议**：绝大多数"融合无效"的案例，**先查归一化和特征尺度**，能解决一半；剩下才考虑梯度手术。

### Q94 ★★ 模型学会了只用一路（单模态惰性）怎么发现和纠正？

**A**：这是融合里最隐蔽的问题——训练指标很好，实际只用了一路。

**发现**：
- 模态消融：屏蔽某一路看指标掉多少（**掉 <1% 基本等于没用上**）
- 门控分布：若某路权重恒接近 0
- 遮挡实验：把图像关键区域抠掉，性能不变 → 说明没在看图

**纠正**：
1. 模态 dropout（最有效）
2. 辅助单模态损失
3. **切断单模态直通路径**：让两路都必须经过融合层才能到检测头（否则强的一路会绕过融合）
4. 降低强模态的输入信息量（如降低分辨率）做对照实验，看是否依赖

**话术**："我判断多模态有没有'真融合'，做的是**遮挡/屏蔽实验**——把一个模态的信息破坏掉，性能应该明显下降；如果不下降，说明融合是装饰。"

### Q95 ★★★ 怎么证明融合真的起作用？（避免自欺）

**A**：五层验证，缺一层都可能自欺：

1. **单模态基线**：同 backbone、同数据、同 schedule、同增广，只去掉融合。**这是唯一有说服力的对照组。**
2. **融合消融**：concat / 门控 / attention 各跑一遍，说明"为什么选这个"。
3. **模态消融（推理时）**：屏蔽任一路，报出各自的退化曲线。
4. **双 seed 噪声地板**：同一配置跑两个种子，**差值就是噪声地板**；融合增益必须显著大于它（不然是随机波动）。
5. **逐类 + 逐距离归因**：把 fp/fn 拆成 no_hit / wrong_cls / early-late（位置偏差）等成分，看融合到底改善了哪一类错误——如果主要改善的是"远处小目标"，和物理直觉一致，结论就站得住。

**面试价值**：这五条一说，面试官会认为你**做过真实的 A/B，而不是只在论文里见过融合**。

### Q96 ★★★ 融合后效果反而变差，怎么定位？

**A**：按"对齐 → 配权 → 信息"三段查：

| 症状 | 大概率原因 | 怎么验证 |
|---|---|---|
| 出现鬼影、目标位置偏移 | **对齐错**（时间戳/外参/畸变） | 静止目标残差检查；投影可视化；扫 Δt 看残差曲线 |
| 某些类别掉分、某些涨 | **配权错**（一路主导） | 门控分布 + 单模态消融；看是否"强模态压制弱模态的有效信息" |
| 整体小幅掉分 | 融合层初始化太激进 / 学习率不对 | 关融合只训分支，再零初始化开融合 |
| 近处变好、远处变差 | **尺度/分辨率失配** | 按距离分段统计指标 |
| 晴天好、雨天崩 | **缺失效增广** | 造退化测试集；加模态 dropout + 退化增广 |
| 训练集好、验证集差 | 融合层过拟合小数据 | 减少融合参数（门控替 attention）、加正则 |

**一句话收尾**："融合出问题，我第一步不是改结构，而是**把对齐和配权这两件事分别量化**——因为 80% 的'融合无效'其实是这两件事没做对。"

## S9 损失函数：从单任务选型到多任务配平

> 这一章按四个层次组织：**① 单任务怎么选**（Q97-Q101）→ **② 占据/3D 任务专用**（Q102-Q106）→ **③ 几何任务**（Q107-Q110）→ **④ 多任务配平与调试**（Q111-Q118）。
> 面试时最容易被问的不是"你知道哪些 loss"，而是**"为什么选这个、怎么配平、怎么证明它有用"**——后三层才是分水岭。

### 损失设计的四个层次（总览）

|---|---|---|

### Q97 ★★★ 分类/分割为什么用交叉熵而不是 MSE？CE 有哪些变体？

**A**：三个层次回答：

1. **梯度层面**：CE + softmax 的梯度是 `p − y`，误差越大梯度越大，**收敛快**；MSE + softmax 的梯度多一个 `p(1−p)` 因子，在 softmax 饱和区（预测很自信但错）梯度趋近 0——**恰恰在最该纠正的时候不动**。
2. **概率层面**：CE 是负对数似然，优化它等价于做最大似然估计；MSE 假设高斯噪声，对"概率分布"这个目标不合适（非凸、非归一化）。
3. **性质层面**：CE 对错误自信的惩罚趋于无穷（`−log p → ∞`），天然抑制过度自信。

**四个必须会讲的变体**：

| 变体 | 公式要点 | 什么时候用 |
|---|---|---|
| **Label Smoothing** | target 从 one-hot 变 `(1−ε)·onehot + ε/C` | 防过度自信、正则化、提升校准；ε 常 0.1 |
| **Focal Loss** | `−α(1−p_t)^γ·log p_t`，γ 常 2、α 0.25 | 极端类别不平衡、大量易分负样本（检测、占用） |
| **Soft-target CE** | 直接用教师分布算交叉熵 | 蒸馏、多标注者标签 |
| **OHEM / hard example mining** | 只对 loss 最大的前 k 个样本回传 | 难例主导的场景；注意别让噪声样本霸占 |

**追问**：focal 的 γ 起什么作用？→ 调节"难易样本的相对权重"：γ=0 退化为 CE；γ 越大，易分样本的权重被压得越狠（`(1−p_t)^γ`），难例占比上升。坑：γ 过大 + 学习率大容易训崩，且对**标签噪声**更敏感（噪声样本天然"难"）。

### Q98 ★★★ 回归损失怎么选？L1 / L2 / SmoothL1 的取舍？

**A**：

| 损失 | 梯度 | 特点 | 适用 |
|---|---|---|---|
| **L2 (MSE)** | 与误差成正比 | 对大误差极敏感，**异常值主导梯度** | 噪声近似高斯、无离群点 |
| **L1 (MAE)** | 恒定（±1） | 对离群点鲁棒，但零点不可导、小误差时梯度不衰减 → 收敛慢、易抖 | 有离群点、需要鲁棒 |
| **SmoothL1 / Huber** | 小误差 L2、大误差 L1 | 兼顾两者，**检测框回归的事实标准** | 绝大多数回归 |
| **log 变换后 L1** | — | 处理跨数量级目标（深度 0.5~100m） | 深度/视差/距离 |

**关键细节（易被追问）**：
- SmoothL1 的拐点 β（PyTorch 默认 1.0）：β 太大会退化成 L2，太小退化成 L1；对归一化后的坐标通常取 1/9（对应 IoU 意义上的 3 像素）。
- **回归前先做目标归一化**（除以均值或 std），否则不同任务（0.1m 的高度误差 vs 10m 的距离误差）梯度量级完全不同——这是多任务配平的第一道门槛。
- 对**方向/角度**回归不要用 L1，用 `sin/cos` 双通道 + CE，或用周期化角度损失（否则 ±π 处不连续）。

### Q99 ★★★ 检测框回归为什么用 GIoU/DIoU/CIoU 而不是纯 L1？

**A**：L1 把 `(x, y, w, h)` 当四个**独立标量**优化，但评测指标是 **IoU**——代理损失与目标不一致。而且：
- 两个框 L1 距离相同，IoU 可能差很多（尺度不同的框）；
- 框不相交时 IoU 恒为 0，**没有梯度**。

演进线（面试按顺序说）：

```text
IoU        : 1 − IoU，不相交时梯度为 0
GIoU       : 加最小闭包框，解决不相交的问题（L_GIoU = 1 − IoU + |C \ (A∪B)|/|C|）
DIoU       : 再加中心点距离/对角线，收敛更快
CIoU       : 再加长宽比一致性项（长宽比用 arctan 避免不可导）
```

**实践结论**：工业检测器**通常是 L1 + IoU 类联合**（L1 提供稳定的独立坐标监督，IoU 提供与指标一致的尺度不变项），而不是只用一个。3D 检测还要处理 yaw 角（用 `sin/cos` 或 bin-based 分类）和尺度差异（不同类别用不同权重）。

### Q100 ★★ 类别不平衡有哪些处理手段？各自什么时候失效？

**A**：五类手段 + 各自的坑：

| 手段 | 做法 | 失效/风险 |
|---|---|---|
| **class weight** | 按频率取倒数，或有效样本数 `1/(1−β^n)` | 极端长尾时权重爆炸，梯度不稳 |
| **Focal Loss** | 降低易分样本权重 | 对标签噪声敏感（噪声=难例） |
| **OHEM** | 取 loss top-k | 前几轮全是噪声样本，训练偏斜 |
| **重采样（含 CBGS）** | 按类平衡分组采样 | **遇到异常帧会引入偏置**（我们的真实踩坑：CBGS 被个别异常数据扰动，采样后分布跑偏，需要先做数据清洗再加权） |
| **损失组合** | CE + Dice / Tversky | 权重不当时 Dice 项主导，分类精度掉 |

**重要认知**：改采样就会改**训练分布**，而评测分布没变——所以**必须分类别报指标**，否则"整体涨了"可能只是采样偏向的假象。

**追问**：Tversky 怎么调漏检/误检偏好？→ `Tversky = TP/(TP + α·FP + β·FN)`。`β > α` 惩罚漏检（提高召回），`α > β` 惩罚误检（提高精度），是"按业务偏好调 F1 家族"的旋钮。

### Q101 ★★ 分割任务什么时候用 Dice / Lovasz / Tversky，而不是纯 CE？

**A**：

| 损失 | 优化目标 | 适用场景 | 缺点 |
|---|---|---|---|
| **CE** | 逐像素独立分类 | 通用基线 | 类别不平衡时易被多数类主导 |
| **Dice** | 区域级重叠 | 小目标、前景占比极低（医学、占用） | 训练不稳定（梯度方差大）、对小错误惩罚不线性 |
| **Lovasz** | **直接优化 IoU（mIoU 的凸代理）** | 目标是 mIoU 的场景 | 实现复杂、对噪声敏感 |
| **Tversky** | 可调 FP/FN 权重 | 有明确漏检/误检偏好 | 超参敏感 |

**实践建议**：`CE（主） + Dice/Lovasz（辅，权重 0.2~0.5）` 是最稳的组合；纯 Dice 训练早期很容易震荡。

**追问（对口你的场景）**：占用预测的评测是 **RayIoU**（沿射线判命中），而训练损失是体素级 CE——**两者并不一致**。所以必须用"逐类 fn/fp 归因"（no_hit / wrong_cls / early-late 位置偏差）来桥接：知道 CE 下降主要改善了哪类错误，才能判断它是否真的对 RayIoU 有利。

### Q102 ★★★ 三态占用（free / occupied / unknown）的损失怎么设？

**A**：核心原则一句话：**unknown 绝不能当负样本**。

三种常见组织方式：

1. **二分类 + mask**：`occupied` 用 BCE，`unknown` 区域用 `ignore_index`/mask 掉。最常用、最稳。
2. **三分类 CE**：free/occupied/unknown 三类，注意各类占比极端不均（free 极多、occupied 少、unknown 中等），要配 class weight 或 focal。
3. **两路输出**：一路预测 `occupied`（BCE），另一路预测 `observed`（是否被观测到，BCE），`free = observed ∧ ¬occupied`。这种解耦的好处是**可解释、可以分别调**——观测不到（unknown）和空（free）在损失里彻底分开。

**为什么 unknown 不能当负样本**：传感器看不到的地方既不是空也不是占用，把它当"空"会让模型学会"看不到就判空"——在遮挡严重、远距离场景会系统性误判（而且这个错误在训练集上看起来没惩罚）。

**追问**：free 标签可靠吗？→ 由 **ray-casting** 生成的 free 标签（射线未被命中段）比 occupied 更可靠（因为 occupied 受遮挡、标注口径影响）。所以实践中可以给 free/occupied **不同的权重**，或对 occupied 用更大的权重（因为它是下游真正关心的）。

### Q103 ★★★ 语义 + 占用联合预测，损失怎么组织？

**A**：两种范式：

- **多任务（多 head 共享特征）**：`L = λ₁·L_det + λ₂·L_sem + λ₃·L_occ`。优点是共享几何表征、互相正则；缺点是**任务冲突**（分类要判别性、占用要几何精度）。
- **级联**：先检测/分割，再把结果喂给占用头。优点是职责清晰；缺点是无法端到端、误差累积。

**我们采用的是多任务**（检测 / 语义 / 三态占用三头共用 BEV 特征），三个头各自的损失按"量纲归一化 + 手工权重"配平，具体权重靠**逐类 fn/fp 归因反推**——先看哪个头拖了整体指标，再调它的权重，而不是网格搜。

**追问**：多任务里的分类头为什么常配 focal 而不是纯 CE？→ 因为 3D 目标极度稀疏（体素里 99% 是背景），纯 CE 会让梯度被背景淹没。

### Q104 ★★ ray-based / depth-aware 占用损失是什么？

**A**：体素级 CE 有个根本问题：**表面内部（被遮挡实体的内部）到底该判 occupied 还是 unknown，标签本身有歧义**。ray-based 损失从渲染思路借过来：

- 对每根相机射线采样若干点，网络给每个点的"占用概率"；
- 用渲染公式把沿射线的占用概率合成终止分布（第一个命中的期望深度）；
- 与 GT 深度（或 GT 射线终止位置）算损失。

好处：① 直接对齐"看到什么"这件事，天然处理遮挡；② 与下游基于深度的评测更一致。

**我们的做法（可以直接讲的四件套）**：
1. **终止分布 CE**：沿射线的离散终止分布做交叉熵（监督"第一个表面在哪"）；
2. **前沿线空 BCE**：把"表面之前"的采样点约束为空（抑制前置虚警）；
3. **面后占用抑制 BCE**：把"表面之后"的采样点压向非占用（抑制"背后有实体"的误判）；
4. **终止点语义 CE**：在终止点（表面）上做语义分类。

**一句话总结**："这四件套把'深度上的第一性'和'语义上的类别'分开监督，比单纯体素 CE 更贴合可见性。"

### Q105 ★★ SDF / TSDF 的监督损失怎么设计？

**A**：四件套：

1. **主损失：截断 L1**
   ```text
   L = |clip(f(x), −δ, +δ) − clip(sdf_gt(x), −δ, +δ)|
   ```
   **必须截断**：远处符号（内/外）不影响表面，且不截断会让网络把算力浪费在远离表面的区域。δ 常取 0.05~0.2m。
2. **Eikonal 正则**：`(|∇f| − 1)²`，强制输出满足距离场性质（梯度模长为 1）。这是 SDF 类方法的标配，能让几何更"干净"、表面更平滑。
3. **表面附近采样**：均匀采样 + **表面附近密集采样**（按距离分桶），否则大部分样本的梯度信息量极低。
4. **符号/内外一致性**：多个视角/多个截断区域拼起来时，符号必须自洽（同一实体内部统一为正），否则融合后出现"半实半虚"。

**TSDF 的差异**：TSDF 天然带截断（±1 归一化），用截断 L1 即可，且**越靠近表面权重越高**（因为远端的 TSDF 值本就不精确），常按 `exp(−|d|/σ)` 或线性衰减加权。

**追问**：SDF 和 TSDF 哪个更适合做表面重建/判据？→ SDF 连续可微、能算梯度求表面法向（Eikonal 天然），适合优化与法向估计；TSDF 是加权平均、抗噪好、适合多帧融合。**判据类任务（表面/边界判定）通常用 SDF 值 + 阈值，用 TSDF 做几何兜底**。

### Q106 ★★ 表面化判据 / 边界 / 前沿线这类任务用什么损失？

**A**：这是"极稀疏二分类"问题，纯 BCE 不行：

- **主损失 BCE + focal**：正样本占比极低，focal（γ=2）或正样本加权（pos_weight = 负/正比）是基线。
- **distance transform 加权**：按每个点到 GT 表面的距离给权重（越近权重越高，如 `w = exp(−d²/2σ²)`），让"差一点就是表面"的区域获得更大梯度——这是边界类任务最有效的一招。
- **软标签 / 模糊带**：把标注本身的不确定性建模成一个带宽（表面附近 1~2 体素的软标签），避免在标注歧义区强行拉满。
- **Dice / Tversky 辅助**：直接优化区域重叠，对小目标边界更敏感。

**面试可讲的点**："边界类任务的瓶颈通常不在损失函数本身，而在**标注一致性**——表面到底算在哪个体素，标注者之间差 1 个体素就足以让 mIoU 抖几个点。所以我会先做双人/双次标注一致性统计，再谈损失调优。"

### Q107 ★★ 立体匹配 / 深度估计的损失怎么设计？

**A**：三部分组合：

1. **主监督：Smooth L1 on 视差/深度**（EPE 指标对应的就是它），只对有效视差（非遮挡、非无效）计算——`mask` 必须做，否则无效区域会污染梯度。
2. **多尺度序列监督**（迭代式方法如 RAFT-Stereo）：每次迭代都算损失，权重随迭代递增（`γ^(N−i)`，γ 常 0.9），让粗到细都受监督。
3. **无监督/自监督分支**（有图像对时可用）：photometric（把右图按预测视差 warp 到左图，算 SSIM + L1）+ **左右一致性**（左右视差互为参考）+ **平滑项**（二阶/TV，边缘处放松）。

**关键细节**：
- **遮挡/无纹理区域要 mask**：这些区域本来就没有匹配信息，强行监督会把噪声学进网络。
- **置信度分支**：用"预测值与 GT 的差"作为置信度监督（差越小置信度越高），推理时可用来滤除不可靠深度。
- **视差归一化**：不同数据集视差范围差异大，先除以均值或做 scale-shift invariant（SSI）归一化。

### Q108 ★★ 单目深度的尺度歧义怎么处理？

**A**：单目没有绝对尺度，直接 L1 会让网络在"整体缩放"上纠缠。三种处理：

1. **尺度不变损失（SSI）**：先对预测和 GT 做最小二乘对齐（scale a、shift b），再算 L1：
   ```text
   (a*, b*) = argmin || a·d_pred + b − d_gt ||²    然后 L = |a*·d_pred + b* − d_gt|
   ```
   这就是 MiDaS 系列的经典做法（位移不变 + 尺度不变）。
2. **对数空间**：`|log d_pred − log d_gt|`，等价于相对误差，对小深度不惩罚过重。
3. **相对深度 / 排序**：只监督相对关系（ordinal regression、pairwise ranking），适合没有绝对 GT 的数据。

**追问**：什么时候必须用绝对尺度？→ 下游要做度量判断（占用、可通行、测距）时必须；纯视觉展示类任务可以用相对深度，再用少量带尺度标注的数据或传感器做**尺度对齐（scale calibration）**。

### Q109 ★ 点云/重建类任务的损失有哪些？

**A**：四种常用：

- **Chamfer Distance**：正反两个方向的最近点距离之和。快，但**对密度不敏感**（点聚在一起也能低分）。
- **Earth Mover's Distance**：最优传输距离，考虑密度，更准但 O(n³) 级别贵（一般用近似）。
- **法向一致性**：`1 − cos(n_pred, n_gt)`，几何质量的关键指标。
- **隐式场损失**（我们用的 SDF/TSDF）：在采样点上监督距离值，见 Q105——现在主流已经从"生成点"转向"生成场再提取表面"，因为场更连续、更容易加 Eikonal 约束。

### Q110 ★ 时序一致性损失怎么加？

**A**：三个层面，从模型到损失：

1. **权重层面（最省）**：EMA 教师模型 + 自蒸馏，或用"上一帧权重"做约束——我们用的是 **EMA（12/24 epoch）**，本质是免费的时序平滑。
2. **预测层面**：用自车运动把上一帧预测 warp 到当前帧，与当前预测算一致性（`|P_t − warp(P_{t−1})|`），只在静态区域计算（动态目标要用光流或 mask 掉）。
3. **特征层面**：时序历史特征与当前特征做一致性/门控（注意别让历史信息"抄近路"导致当前帧不学）。

**坑**：一致性损失对**对齐误差**极敏感——自车运动估计不准时，一致项会把误差"学成规律"。所以要先确认位姿/时间同步质量（同 S8 的对齐原则）。

### Q111 ★★★ 多任务 loss 权重怎么定？（这是面试最爱问的）

**A**：五类方法，按落地顺序：

| 方法 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **① 量纲/量级归一化** | 各项先除以初始值或滑动均值，再给权重 | **成本最低、最有效** | 依赖初始值选择 |
| **② 手工权重 + 网格/贝叶斯搜索** | 按经验设比例如 1:1:0.2 | 可控 | 任务多了搜不动 |
| **③ 不确定性加权（Kendall）** | 每项学 `log σ²`，`L = Σ exp(−log σ²)·L_i + log σ²` | 自动、有理论 | σ 会漂，要 clamp |
| **④ GradNorm** | 按各任务梯度范数动态调整，使收敛速度同步 | 针对"学得慢的任务" | 要算梯度范数，开销大 |
| **⑤ DWA（动态权重平均）** | 按最近窗口的 loss 下降比率调权 | 简单有效 | 权重可能震荡，要平滑 |

**我们的实际做法（能直接讲）**：先用 ① + ② 打底（多尺度深监督的粗头权重 0.2，各头量纲先归一化），再用**逐类 fn/fp 成分解剖**反推要不要调——比如发现某类主要是 `wrong_cls`（分类错），就加分类头的权重；发现是 `no_hit`（根本没预测到），就加召回相关的项（focal 的 α 或正样本权重）。**这一套比网格搜索快，也更容易解释。**

**追问**：权重需要随训练阶段变吗？→ 需要。常见做法是辅助头权重**随 epoch 衰减**（前期帮助收敛、后期让主任务主导），主任务权重保持稳定。

### Q112 ★★★ 深监督 / 辅助头怎么加权？

**A**：三条经验：

1. **辅助权重小**：典型 0.1~0.4。太大 → 辅助任务主导，主任务学偏；太小 → 没作用。我们用的 **ASPP 粗头权重 0.2**，收敛期主 loss 降了约一个量级。
2. **随训练衰减**：`w(t) = w₀·(1 − t/T)` 或按平台期衰减，让后期主任务独占梯度。
3. **辅助头设在"信息瓶颈之前"**：放在较浅/较粗尺度的强任务（如粗粒度语义），能提供更密集的梯度；放在深层反而容易和主头冲突。

**坑**：辅助头如果用同一份标签（就是主任务的多尺度版本），要注意**标签分辨率与预测分辨率一致**（下采样标签时用最近邻而非插值，否则边界变模糊，辅助头学的是假梯度）。

### Q113 ★★ 梯度冲突 / 负迁移怎么处理？

**A**：四步：

1. **先判断是否真的冲突**：算两个任务梯度的余弦相似度，长期为负才是真冲突。
2. **PCGrad（梯度手术）**：冲突时把一方梯度在另一方的正交方向上投影掉，消除方向冲突分量。
3. **参数隔离**：冲突严重的任务不共享全部 backbone（共享浅层、任务专属深层，或多分支头）。
4. **训练顺序**：先各自单任务预热，再联合微调（避免早期强任务压制弱任务）。

**实测建议**：优先级是 **归一化 > 权重调整 > 参数隔离 > PCGrad**。绝大多数"多任务训不好"是前两项没做对，GradNorm/PCGrad 是最后的补丁。

### Q114 ★★ 训练中动态调权要注意什么？

**A**：三条纪律：

- **必须平滑**：DWA 这类按窗口算比率的方法，对单个 batch 的噪声极敏感，要做 EMA 平滑（否则权重在高频震荡）。
- **必须有上下界**：任何动态权重都做 clamp（如 [0.05, 5]），否则某项会一路涨到"吃掉整个训练"。
- **必须监控**：把各项 loss 和权重分别画曲线，权重剧烈变化的时刻往往对应数据分布问题（异常帧、某个传感器数据缺失），而不是模型问题。

### Q115 ★★★ loss 一直在降，但指标不涨，怎么查？

**A**：五个方向，按概率排：

1. **代理与指标不一致**：loss 优化的是体素 CE/L1，评测指标是 RayIoU/mAP——两者不同步是常态。**做法：把评测指标的错误拆成分项**（no_hit / wrong_cls / 位置偏差），看 loss 下降改善了哪一项。如果改善的是评测不关心的部分（如远处海量 free 体素），那 loss 降而指标不动完全是合理的。
2. **评测噪声地板**：同一配置跑两个 seed，差值就是噪声。指标变化小于噪声地板时，"不涨"可能是假象——我们做双 seed 噪声地板的直接动机就是这个。
3. **过拟合/数据泄漏**：训练集 loss 降、验证集指标不动；或验证集和训练集有近重复帧。
4. **类别不均衡掩盖**：整体 loss 被多数类主导，少数类的恶化被冲掉。必须分类看。
5. **后处理/解码不一致**：训练用 CE 优化概率，解码用阈值 0.5 或 top-k，阈值没调过的话指标自然不涨。

**面试话术**："我判断损失项是否有效，不看 loss 数值，看**指标的分项归因**和**双 seed 噪声地板**——先确认指标变化超出噪声，再确认改善落在错误的哪个成分上。"

### Q116 ★★★ 某一类永远学不会，怎么定位？

**A**：六步查，从数据到结构：

1. **标签**：数量是否极少？有没有越界/映射错？（我们的真实案例：CE 的 target 越界，根因是 `cls_num` 参数与实际类别数不一致——loss 直接崩，而不是"学不会"）
2. **是否被 ignore/mask 掉**：某些类在特定距离/视角下被裁掉或标为 unknown。
3. **权重**：class weight 是否让这类几乎不产生梯度。
4. **分辨率/感受野**：小目标在 BEV 0.6m/格 下可能只占 1~2 格，必须有对应尺度的特征（多尺度/高分辨率头）。
5. **特征可分性**：可视化该类的特征分布，看是否和相近类糊在一起（→ 需要更强监督：边界、法向、时序）。
6. **评测口径**：RayIoU 的 `no_hit` 高说明"根本没预测到"，`wrong_cls` 高说明"预测到了但类错"——两条路的解法完全不同。

### Q117 ★★ loss 出现尖峰 / 爆掉，处理顺序？

**A**：严格按这个顺序（我们踩过三连，已知最高效的路径）：

1. **数据**：label 越界、空样本、异常帧（先做数据完整性断言：类别 id 范围、尺寸一致、无 NaN）；
2. **数值**：bf16/fp16 溢出 → 换 bf16 或加 loss scaling；log/exp 未在数值稳定域计算（softmax/CE 没减 max）；
3. **超参**：学习率过大、缺 warmup、梯度裁剪（通常 clip 1.0）；
4. **结构**：新加层初始化不当（零初始化/恒等初始化）、残差尺度、归一化层 eps；
5. **硬件/框架**：GEMM workspace 不足、显存碎片、分布式通信超时（这类报错常伪装成算子错误，例如 `CUBLAS_STATUS_ALLOC_FAILED`）。

**一句话**："先证伪数据，再证伪数值，最后才怀疑模型——顺序错了会浪费一整天。"

### Q118 ★★ 怎么证明某个损失项真的有效？

**A**：四层证据：

1. **消融**：关掉该项，其余完全不变（同 seed、同 schedule），看指标变化是否超过噪声地板。
2. **曲线分离**：画出"有/无该项"的**评测指标**曲线（不只是 loss 曲线）——很多项能让 loss 降但指标不变。
3. **分项归因**：确认改善落在预期的错误成分上（如加了面后抑制项，应主要降低"背后虚警"而不是近处漏检）。
4. **正交性检查**：两项一起加的增益 ≈ 各自增益之和，说明它们解决的是不同问题；若一条加完另一条就没用了，说明二者冗余（面试官很吃这一套分析）。

| 任务头 | 损失 | 关键设置 |
|---|---|---|
| **3D 检测** | 分类 focal + 框回归平滑 L1 + IoU 类项 | 分类配 focal 抗背景稀疏；yaw 用 sin/cos 双通道 |

| **立体/深度** | 平滑 L1（有效视差 mask）+ 多尺度序列监督 | 迭代步间权重 γ^i；遮挡区 mask 掉 |

**三条踩过的坑（讲这些比讲配置更有说服力）**：
1. **CE target 越界**：参数名与实际类别数不一致，loss 直接崩——所以现在数据加载加了 id 范围断言。
2. **CBGS 被异常帧扰动**：class-balanced 采样一旦遇到脏数据，训练分布跑偏，整体指标虚高而单类别变差——所以采样前必须先清洗。
3. **深监督标签下采样用插值**：导致边界模糊、辅助头学假梯度，改成最近邻后曲线才对。
